# Record one execution result


For a reserved argv CMD, use the host executor before recording its actual result. Respect host restrictions and preserve unknown outcomes. Each VAL uses its declared verification source; independently authorized OP retains its external-effect requirements.

1. After the reserved CMD, OP, or VAL finishes, save pure `work-record-finish-request` JSON as the request file and invoke `<work-cli> execute record-finish --input-file "<request-path>"` with the same TASK and execution paths. Omit `record.id`, `record.kind`, and command correction: The Work CLI derives them from the validated active lock and formal TASK, including retry suffixes. Accurate recording of an authorized operation does not require another confirmation; uncertain or expanded effects stop under the Attempt authorization boundary.
2. Command uses actual `exit_code` and `result`; the CLI verifies owned current receipts. Operation uses `outcome` and `state`. VAL uses the declared Task method with `outcome`: `automated` evaluates complete actual CMD output and frozen reports, using explicit verification when present or actual zero exit for every declared command otherwise; explicit conditions may require nonzero. Missing, truncated, oversized or unknown evidence is refused even inside `any` or `not`. `ai_review` supplies `review` with the exact declared reviewer, a concrete rationale and references to artifact bytes, owned command receipts or retained complete file changes; use `contract describe work-record-finish-request` for fields. `manual` supplies `confirmation` with the path/hash of the designated user's actual JSON statement, bound to the exact `validation_context` returned by record-begin. Preserve the original user source and source reference; never invent or paraphrase an AI judgment as user confirmation. These provenance records do not cryptographically authenticate another process running as the same OS user. The writer assigns source, current file version and frozen proof; callers cannot supply `source`, `file_version`, `execution_evidence`, `verification_evidence`, `review_evidence` or `confirmation_evidence`. A bare passed label cannot replace any source's evidence. Do not repeat command correction or report-capture writes as formal `modified_files`.
3. The command validates the formal record and current instruction fingerprints, moves a locked command correction into the command record, atomically appends the canonical Attempt record, updates cumulative modified files and operation outcome, derives acceptance results from the current TASK validation mappings and actual VAL evidence, synchronizes those results into the Execution index, then removes `record_id` and its correction from the lock. It never executes the record or releases the Attempt lock.
4. `recovery_required: true` is a hard stop. Preserve the Attempt, lock, and transaction files; do not resubmit the result or begin another record until separately authorized recovery handles the state.
