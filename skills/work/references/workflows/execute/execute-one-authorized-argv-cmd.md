# Execute one authorized CMD

1. After `record-begin` and any approved `command-correction`, run `<work-cli> execute command-binding` with the explicit Task and Execution context. Check the reserved record ID, exact command, execution settings, capture policy, authorization SHA and file version against the approved scope. The binding is read-only and does not grant Host permission.
2. Execute the bound command through the Host under the existing authorization. Preserve the observed exit code and complete raw stdout, stderr and declared reports. A rejected, unknown or partial Host result cannot finish the CMD. Do not invent an exit code or rerun an uncertain operation to discover its outcome.
3. Save captures in a project-local evidence directory outside `outputs/work`: `stdout.bin`, `stderr.bin` and declared `report-0000.bin` files. Save a `CommandCapturedEvidence` JSON document with each file's exact byte count, raw SHA-256 and completeness. Preserve these files; Work rereads them for VAL and closed Attempt verification.
4. Submit `work-record-finish-request` with `record.host_report`. The `work-host-execution-report` contains the binding's Task, Attempt, record, collection, authorization, file version and command SHA values. `result_reference` points to the capture JSON, and `result_sha256` is its raw SHA-256. Set `result_origin` to `host_reported`, `status` to `exited`, and include the observed exit code with `output_complete: true`. Work generates the frozen `host_binding` and formal record after checking the evidence.
5. A known nonzero exit remains a real result. Explicit automated conditions may require it; otherwise validation fails. Changed inputs, capture bytes, reports, file version or authorization require a new authorized CMD instance. Preserve uncertain and historical evidence. Work verifies old Work-owned receipts under their original format.
