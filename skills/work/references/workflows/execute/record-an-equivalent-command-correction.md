# Record an equivalent command correction


1. A reserved CMD may use an equivalent correction or a reviewed test/diagnostic adjustment within a scope that explicitly permits command adjustments. Preserve its goal, working directory and risk boundary; provide the current DeviationImpact review in impact. Exact-list authorization still requires its exact preapproved replacement. Changed safety, effects or requirements need a new decision.
2. Save pure `work-command-correction-request` JSON as the request file and invoke `<work-cli> execute command-correction --input-file "<request-path>"`. Include the authorized `actual_command` and a non-empty semantic reason, plus impact when reusing scoped authorization. Use `{"mode":"argv","argv":["tool","--fixed"]}` or `{"mode":"shell","script":"tool --fixed"}` for `actual_command`; each form requires its listed value and forbids the other form's fields and formal record IDs. The Work CLI derives the reserved record and effective original command from the active lock, TASK, Attempt, and approved deviations.
3. Require `work-command-correction` with `correction_status: recorded` and `lock_status: record_reserved` before executing the corrected command. The tool verifies the original formal command and stores the correction in the lock; it does not execute the command or decide semantic equivalence.
4. `recovery_required: true` is a hard stop. Preserve the record lock and `.work-command-correction-*.tmp`; do not execute or resubmit until separately authorized recovery handles it.
