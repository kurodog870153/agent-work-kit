# Work and Tooling Policy Boundaries

1. [Required] Work and Tooling are independent Skills. The Host may activate either or both according to the operation; neither Skill directs the Host's tool choice, native Subagent use, permission dialog or execution scheduling.
2. [Required] Work CLI validates formal Source, TASK, Instruction Selection, Attempt authorization, Evidence, state transitions and Artifact transactions. Tooling CLI validates the applicable Policy Source Set. Tooling Policy identity and fingerprint remain separate from Work `required_instruction_sources`, `source_order`, Selection Manifest and TASK fingerprint.
3. [Required] A Work operation blocked by invalid formal state, missing user approval, scope mismatch or Source drift cannot proceed because Tooling Policy is valid. A Tooling-dependent operation with invalid or missing Policy cannot proceed because Work formal state is valid. Either failure blocks only dependent operations.
4. [Required] The Host selects applicable Tooling Capability／Interface／Family branches and checks semantic tool fitness, actual target, side effects, session and permission. Tooling CLI validates sources, hierarchy, ancestors, References, SHA/fingerprint, drift and machine-checkable conditions. A Host claim of `tool_fit` or `authorized` is not independent Tooling CLI verification.
5. [Required] Tooling does not enlarge Work authorization or create a parallel Attempt, audit or Recovery. When formal recording is needed, the Host calls Work CLI with source-labelled results and current formal bindings. Host-reported successful execution may support Work VAL under its formal result contract; Work verifies identity, scope and version without claiming it executed the tool.
6. [Required] On unknown or partial results, inspect actual files and external effects before considering a retry. Preserve existing Work Attempt and Recovery authority and immutable history; do not infer an atomic project edit or an external side effect from Tooling Policy validity.
7. [Required] Work-only and Tooling-only installations remain usable. A missing Tooling Skill cannot invalidate unrelated Work operations; an invalid Work Artifact cannot invalidate independent Tooling Policy inspection.
